---------------------------------------------------------------------
 VISÃO GERAL: O QUE É O DEPLOY
---------------------------------------------------------------------
Deploy é tirar o sistema do seu computador e colocar na internet.
Depois, qualquer pessoa abre um link e usa, com seu PC desligado.

  Parte    Hoje (seu computador)            Depois (internet)
  -------  -------------------------------  ------------------------------------------
  Site     npm run dev -> localhost:5173    Vercel -> cti-front-SEUNOME.vercel.app
  Java     mvn spring-boot:run -> :8080     Azure  -> cti-api-SEUNOME.azurewebsites.net
  Python   uvicorn -> :8000                 Azure  -> cti-python-SEUNOME.azurewebsites.net
  Banco    Azure PostgreSQL ou Neon         continua onde está

O .env NÃO vai junto: o que está nele é cadastrado de novo em
"Variáveis de ambiente" de cada Aplicativo Web.

Ordem: PREPARAR -> VARIÁVEIS (.env) -> BANCO -> PYTHON -> JAVA -> SITE -> CORS -> TESTAR

--- 0.2 Criar frontend/vercel.json ----------------------------------
VS Code -> botão direito na pasta frontend -> New File -> vercel.json

  {
    "rewrites": [
      { "source": "/(.*)",
        "destination": "/index.html" }
    ]
  }

  "rewrites"      -> lista de regras para "reescrever" o endereço
  "source"        -> qualquer endereço: /dashboard, /upload, /login...
  "destination"   -> entrega sempre o index.html (onde o Vue mora)
  Sem ele, apertar F5 em /dashboard dá 404.

=====================================================================
 VARIÁVEIS DE AMBIENTE (.env): O QUE SÃO E ONDE VÃO
=====================================================================
O .env guarda o que muda de um lugar para outro: endereço e senha do
banco, segredos e endereços dos outros serviços. O código só lê o NOME
da variável; o VALOR fica fora dele.

  .env.example -> modelo SEM senhas, com os nomes. VAI para o GitHub.
  .env         -> cópia com os valores reais, SÓ no seu computador.
                  NUNCA vai para o GitHub (o .gitignore impede).
  Na nuvem     -> os mesmos nomes, cadastrados no painel:
                  Azure: app -> Configurações -> Variáveis de ambiente
                  Vercel: Settings -> Environment Variables

  Pasta                   Quantas   Onde cadastrar no deploy
  ----------------------  --------  -----------------------------------------
  backend/.env            9         Azure -> cti-api-SEUNOME
  analytics-python/.env   7         Azure -> cti-python-SEUNOME
  frontend/.env           1         Vercel

TODAS AS VARIÁVEIS (mesmo nome, valor de cada lugar):

  Variável              Onde          No .env (computador)            Na Azure / Vercel
  --------------------  ------------  ------------------------------  -----------------------------------------------
  DB_URL                Java          jdbc:postgresql://HOST:5432/ctiinsights?sslmode=require   (o mesmo)
  DB_HOST               Python        HOST do banco                   o mesmo
  DB_PORT               Python        5432                            5432
  DB_NAME               Python        ctiinsights                     o mesmo
  DB_SSLMODE            Python        require                         require
  DB_USER               Java+Python   usuário do banco                o mesmo
  DB_PASSWORD           Java+Python   senha do banco                  a mesma
  JWT_SECRET            Java          qualquer texto longo            SEGREDO_1
  ETL_KEY               Java          o mesmo texto do ETL_API_KEY    SEGREDO_2
  ETL_API_KEY           Python        o mesmo texto do ETL_KEY        SEGREDO_2
  ETL_URL               Java          http://localhost:8000/etl       https://cti-python-SEUNOME.azurewebsites.net/etl
  ADMIN_EMAIL           Java          seu admin de teste              SEU_EMAIL
  ADMIN_PASSWORD        Java          senha do admin de teste         SENHA_FORTE
  CORS_ORIGINS          Java          http://localhost:5173           https://cti-front-SEUNOME.vercel.app
  VITE_API_URL          Site          http://localhost:8080/api       https://cti-api-SEUNOME.azurewebsites.net/api
  SCM_DO_BUILD_DURING_DEPLOYMENT  Python (só na Azure)               true

Só mudam os endereços (localhost -> internet) e os segredos.
O nome tem que ser EXATAMENTE igual: maiúsculas e _ contam.

 PASSO 6 · ERROS COMUNS
=====================================================================
Actions ✘: requirements.txt not found
  -> faltou trocar as 2 linhas do .yml do Python (passo 2.3)
Actions ✘: no POM in this directory
  -> faltou trocar as 2 linhas do .yml do Java (passo 3.3)
Erro de região ou de política ao criar
  -> use uma das regiões que a mensagem lista, a mesma em tudo
Python mostra a página padrão da Azure
  -> falta o Comando de inicialização (passo 2.2)
Log: Connection timed out no banco
  -> Rede do PostgreSQL: "Permitir acesso de serviços do Azure"
Log: password authentication failed
  -> DB_USER ou DB_PASSWORD errado nas variáveis
Log: Could not resolve placeholder
  -> faltou uma variável no Java (o nome aparece no erro)
blocked by CORS policy (F12)
  -> CORS_ORIGINS = endereço exato da Vercel, sem / no fim
404 ao apertar F5 no /dashboard
  -> falta o frontend/vercel.json no GitHub
Upload com erro 502 ou 503
  -> ETL_KEY diferente de ETL_API_KEY, ou ETL_URL errado: abra /saude

Onde olhar:
  GitHub -> aba Actions (clique na execução com ✘ e leia o passo vermelho)
  Azure  -> o app -> Monitoramento -> Fluxo de log
  Vercel -> Deployments -> Build Logs
  Site   -> F12 -> Console

SEGURANÇA: os valores reais ficam SÓ no bloco de notas e nas
variáveis de ambiente da Azure. Nunca no código, no GitHub, em prints
ou em slides.
