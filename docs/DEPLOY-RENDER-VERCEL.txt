---------------------------------------------------------------------
 VISÃO GERAL: O QUE É O DEPLOY
---------------------------------------------------------------------
Deploy é tirar o sistema do seu computador e colocar na internet.
Depois, qualquer pessoa abre um link e usa, com seu PC desligado.

  Parte    Hoje (seu computador)            Depois (internet)
  -------  -------------------------------  ----------------------------------
  Site     npm run dev -> localhost:5173    Vercel -> cti-front-SEUNOME.vercel.app
  Java     mvn spring-boot:run -> :8080     Render -> cti-api-SEUNOME.onrender.com
  Python   uvicorn -> :8000                 Render -> cti-python-SEUNOME.onrender.com
  Banco    Neon (ou Azure)                  continua onde está

O .env NÃO vai junto: as senhas dele são digitadas de novo no painel
de cada serviço (por isso há tantas variáveis).

Ordem: PREPARAR -> PYTHON -> JAVA -> SITE -> AVISAR O JAVA (CORS) -> TESTAR

--- 0.2 Criar frontend/vercel.json ----------------------------------
VS Code -> botão direito na pasta frontend -> New File -> vercel.json

  {
    "rewrites": [
      { "source": "/(.*)",
        "destination": "/index.html" }
    ]
  }

  O que faz cada linha:
  "rewrites"      -> lista de regras para "reescrever" o endereço
  "source"        -> qualquer endereço: /dashboard, /upload, /login...
  "destination"   -> entrega sempre o index.html (onde o Vue mora)

  Por que precisa: sem ele, apertar F5 em /dashboard dá 404.

--- 0.3 Criar backend/Dockerfile ------------------------------------
Botão direito na pasta backend -> New File -> Dockerfile
(D maiúsculo, SEM extensão)

  FROM maven:3.9-eclipse-temurin-21 AS build
  WORKDIR /app
  COPY pom.xml .
  RUN mvn -q dependency:go-offline
  COPY src ./src
  RUN mvn -q clean package -DskipTests

  FROM eclipse-temurin:21-jre
  WORKDIR /app
  COPY --from=build /app/target/cti-provedor-api.jar app.jar
  EXPOSE 8080
  ENTRYPOINT ["java", "-XX:MaxRAMPercentage=75", "-jar", "app.jar"]

  O que faz:
  ETAPA 1 (FROM maven...)   computador com Maven + Java 21
    WORKDIR /app            trabalha na pasta /app
    COPY pom.xml / RUN ...  copia o pom.xml e baixa as bibliotecas
    COPY src / RUN ...      copia o código e gera o .jar
  ETAPA 2 (FROM ...-jre)    computador leve, só com Java para rodar
    COPY --from=build       traz só o .jar pronto da etapa 1
    EXPOSE 8080             avisa a porta do Java
    ENTRYPOINT              liga o Java usando no máximo 75% da memória

  Por que precisa: o Render não tem Java pronto. O Dockerfile é a
  "receita" que ensina o Render a compilar e rodar o backend.

[ ] Dockerfile criado dentro de backend

 PASSO 5 · ERROS COMUNS
=====================================================================
blocked by CORS policy (F12)
  -> CORS_ORIGINS = endereço exato da Vercel, sem / no fim
404 ao apertar F5 no /dashboard
  -> falta o frontend/vercel.json no GitHub
"Não consegui falar com o servidor"
  -> VITE_API_URL errado (https e /api no fim) -> Redeploy na Vercel
Upload com erro 502 ou 503
  -> Python dormindo ou ETL_URL errado: abra /saude e envie de novo
Log: password authentication failed
  -> DB_USER ou DB_PASSWORD errado no Render
Log: Chave do ETL inválida
  -> ETL_KEY (Java) diferente de ETL_API_KEY (Python)
Log: Could not resolve placeholder
  -> falta uma variável no Render (o nome aparece no erro)
Build do Render falhou
  -> Root Directory errado, ou falta o Dockerfile na pasta backend
Primeiro acesso muito lento
  -> normal no grátis: espere 1 minuto

Onde olhar: Render -> Logs · Vercel -> Deployments -> Build Logs ·
Site -> F12 -> Console

SEGURANÇA: os valores reais ficam SÓ no bloco de notas e nos painéis.
